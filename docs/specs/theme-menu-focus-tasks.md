# B 主题菜单焦点 · Design 任务

依赖[同版方案](theme-menu-focus-design.md)与[已确认规格](theme-menu-focus.md)。本页是实施顺序和完成条件。

## T1 · 用生产接缝做焦点红绿验证

- **范围**：`src/panels/config_panel.cpp`、一个只依赖 C++17 标准库的内部头文件（建议放 `include/panels/theme_menu_focus.h`），以及 `test/host/cases/theme_menu_focus/` 的单个可执行套件。
- **步骤**：引入由生产面板调用的小接缝，先保持返回 0 的旧行为。用同一 host runner 跑已保存 Night 断言，留失败日志。再实现保存值匹配，仅对主题枚举子菜单启用，并将结果同时用于操作与显示索引。
- **完成**：对应断言由红转绿，焦点套件及原有主机冒烟都运行。审查非主题菜单、短按、保存标记、Back、长按写配置及车灯逻辑的边界。构建 `test-wokwi` 成功后，本地提交供 T2 验收。此提交是待验候选，B1–B5 的规格通过条件在 T2 判定。
- **理由**：测试先观察旧行为，再使用同一生产决策复验；一个套件入口匹配现有 runner 按目录编译的方式。

## T2 · 准备并执行 B1–B5 的候选固件验收

- **依赖**：T1。将用于重复运行的场景准备为独立的 `test/wokwi/` 场景改动。通用旧场景留作参考，避免扩大本次修改。
- **内容**：按[场景步骤与证据](theme-menu-focus-design.md#wokwi-场景步骤与证据)准备三个独立场景。第一组核对 B1 和浏览后返回 B3；第二组核对保存及重进 B4 和直接确认 B2；第三组核对车灯临时变色时的 B5。
- **完成**：按方案从待验提交重建，绑定源码 SHA 与 BIN 摘要。记录场景、退出码、串口和 LCD 画面，B3 对照 B4；逐项回填 B1–B5 的实测结果。工具链、按键时序或画面取证有缺口时保留阻塞，修正后同版复跑。
- **理由**：浏览和保存最终都表现为一次菜单重进。同版对照能分辨实际保存变化并捕获面板索引与显示索引接错的问题。
