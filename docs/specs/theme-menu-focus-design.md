# B 主题菜单焦点 · Design

审阅稿。对应[已确认规格](theme-menu-focus.md)与[确认回执](theme-menu-focus-define-approval.md)。实施见[任务清单](theme-menu-focus-tasks.md)。代码基线为 `e3ea788eefe9b18e992658b249819c3ad992f93f`。

## 已核实的现状

- `ConfigPanel::ShowOptionsMenu` 构造主题选项和 Back 后，将屏幕的索引和面板内部索引都设为 0。主题选项顺序是 Day、Night，因此已保存 Night 时，长按执行的仍是 Day。
- `ShowEnumOptionsMenu` 根据 `ConfigItem::value` 生成已保存标记 `> `。短按更新导航索引，长按按面板索引执行该项动作，保存入口是 `HandleSetConfigValue`。
- 车灯通过 `SetTheme` 改运行时画面。它没有走菜单的配置更新路径。当前 Wokwi 通用场景还等待本版源码中已经不存在的主题菜单旧串口文案。见[主题 Wiki](../wiki/theme-and-config-menu.md)和[源码](../../src/panels/config_panel.cpp)。

以上是源码核对。B1–B5 的候选固件行为留待实跑。

## 设计决定

| 决定 | 原因及适用条件 |
| --- | --- |
| 主题初焦点复用当前配置值和原始 Day / Night 选项。 | 同一份配置值已有已保存标记，临时换色期间也能找到用户真实保存的选项。按原始选项匹配，无需解析渲染标签或长按动作字符串。 |
| 只在 `style_manager.theme` 的枚举子菜单启用保存值匹配。菜单构建完成后，面板和组件用同一个索引。 | 这把变化限制在已确认的菜单，并保证屏幕居中项与下一次长按执行项一致。扩展到其他枚举会改变既有行为，当前规格没有这一需求。 |
| 提取一个仅依赖标准库的内部索引决策，让实际面板和主机用例调用同一份代码。 | 直接内联最省文件，但现有主机入口无法编译依赖 LVGL 的整个面板。小接缝可以验证初始索引，并保留固件实测检查接线。 |
| 主机单测验证索引计算，Wokwi 验收实际按键和配置结果。 | 纯索引用例不能证明按钮接线、保存或显示正确。B3 和 B4 的重进画面并排留证，可以直接区分浏览后返回和长按保存。 |

## 实施接口与调用顺序

内部口径为 `InitialOptionsFocusIndex(focusSavedValue, options, savedValue)`，返回零基索引。布尔开关只在上述主题菜单匹配时启用。输入是原始选项及保存值，输出只表示初始焦点。返回值 0 沿用“从首项打开”的现有行为，适用于其他菜单、无匹配或空选项。配置读取、项的构造、选项次序、Back、样式刷新及长按保存均保留在现有调用方。

面板依次解析选项、构造含 Back 的完整菜单、确定初始索引，再用同一个值设置内部索引和组件索引。查找只覆盖原始可保存选项，Back 不参与匹配。无需修改持久化格式、公共接口或固件环境。回滚实现提交即可恢复原先的首项焦点行为。

## 验证与护栏

| 护栏 | 证据 |
| --- | --- |
| **主机红绿** | 按保持原行为的接缝先运行主题套件，已保存 Night 时，实际为 0、期望为 1 的行为断言先失败；修改后同一用例通过。覆盖 Day、Night、非主题、查无匹配，并记录用例名和退出码。 |
| **接线与范围** | 审查同一候选的源码差异，确认两个索引取自同一决策，开关限定于主题。检查短按、Back、长按写配置、已保存标记及车灯路径沿用现有入口。 |
| **固件与 Wokwi** | 从待验提交创建独立构建目录，外置配置固定 LVGL `9.2.2`，构建 `test-wokwi`，记录 SHA 和 BIN 摘要。Wokwi CLI 只加载相同 BIN，实际 CLI 场景执行 B1–B5，记录 LCD 和串口。 |
| **可观察信号** | 重进菜单时分别观察居中高亮与 `> ` 标记。B3 先浏览到 Night，继续到 Back 后返回，按实际菜单层级重进。B4 真正保存 Night 后重进。B5 先证明仪表出现临时 Night，再打开主题菜单核对 Day。 |

Wokwi 的候选脚本使用现有按键 `btn1` 和车灯控件 `trigger_btn4`，从 `lcd1` 取证。根据当前菜单层级和串口实际标记编排步骤。旧场景的失效文案不作通过依据。每组在明确的初始保存值下运行；截图和行为证据缺失时保留待验收状态。

### Wokwi 场景步骤与证据

从独立模拟实例启动。通过实际菜单确认或先保存 Day，再开始对应组。进入 Theme 的共同路径为仪表长按 → 配置 → Display → Theme。以现有场景的 800 ms 短按、2000 ms 长按为起点，释放后等待界面稳定。使用当前构建确实输出的按键和灯光标记，界面以 LCD 为准。

| 组别 | 步骤 | 取证与通过条件 |
| --- | --- | --- |
| B1、B3 | 已保存 Day。打开 Theme，短按至 Night，再短按至 Back。长按 Back，返回配置主菜单，沿 Display → Theme 重进。 | 首次 Day 居中。浏览到 Night 时，Night 居中且 `> ` 仍标 Day。返回后重进，Day 居中且仍有保存标记。 |
| B4、B2 | 独立从已保存 Day 开始。短按到 Night，长按保存，沿返回后的菜单重进 Theme。确认此时直接长按，再次重进。 | B4 重进时 Night 居中且有保存标记。B2 直接确认前和再次重进后，焦点都在 Night，保存标记也保持在 Night。 |
| B5 | 独立从已保存 Day 开始。按住车灯输入，待仪表临时显示 Night，再进入 Theme。最后释放车灯。 | 先留仪表临时 Night 画面及灯光串口，再留 Theme 内 Day 居中且有保存标记的画面。 |

每组按待验提交和 B 编号保存脚本、关键画面与串口。B3 和 B4 使用相同的起始保存值和菜单入口，便于直接对照是否发生了保存变化。
