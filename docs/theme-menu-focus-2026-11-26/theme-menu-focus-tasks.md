# 主题菜单焦点 · Design 任务清单

仓库为 Clarity。以上游已确认规格 `b0baf9b2` 和 [Design 方案中的接口、命令、证据规则与检查矩阵](theme-menu-focus-design.md) 为准。每项包含可独立运行的检查，实施时作为单笔完整变更提交。

## T1 · 建立实际固件的验证入口

- **依赖与范围** 无上游开发任务。新增 `test/wokwi/theme_menu_focus/run.sh`、`probe.yaml` 及最小场景执行辅助，复用现有电路图。测试构建观察点限于 `src/handlers/action_handler.cpp`、`src/providers/storage_provider.cpp`、`src/components/config_component.cpp`、`src/managers/style_manager.cpp` 的实际入口。
- **动作** 按方案生成并校验完整模拟镜像，执行 `--case probe`。以 GPIO32 打开主题菜单并显式保存 Day，随后回仪表用 GPIO33 开灯和关灯。运行器按动作边界采集写入、菜单配色与灯光配色事件，截获稳定的 LCD 帧；检查观察代码仅在模拟测试构建生效。入口缺凭证、模拟失败、截图缺失或记录不全时返回失败。
- **完成标准** 主机冒烟、固定版本的 `test-wokwi` 构建通过。Probe 实跑有真实按键分发及确认完成、成功写入和菜单配色的阳性记录、有 Night/Day 的车灯触发和共享配色记录，并能从稳定动作生成可判读的 LCD 图片。同版保存 SHA 和镜像摘要。该提交保留基线的初始焦点行为，为 A1 红测和 A4 对照提供带观测的基线。

## T2 · 修复并验证主题初始焦点

- **依赖与范围** 依赖 T1。只在 `src/panels/config_panel.cpp`、`include/panels/config_panel.h` 实施 ADR，新增本组 `A1.yaml`、`A2.yaml`、`A3.yaml`、`A7.yaml` 或等价的分支场景文件，均位于 `test/wokwi/theme_menu_focus/`。
- **动作** 先用 A1 脚本跑 T1 产物，留存 Night 已保存时菜单高亮 Day 的失败证据。再实现一次匹配及双索引对齐，按同一验法检查 A1、A2、A3、A7。A2 的有值和空 NVS 独立启动，A3 留短按循环的多帧，A7 初开和标记检查分别取帧。
- **完成标准** A1 基线因焦点断言失败，候选通过同一业务检查。A2、A3、A7 均通过。记录直接长按实际保存的值。主机冒烟、固定版本固件构建和生产差异检视通过。此提交只闭环焦点修复及本组检查，后续验收另按清单执行。

## T3 · 验证车灯换色与主题预选分离

- **依赖与范围** 依赖 T1、T2。只新增 `test/wokwi/theme_menu_focus/A5*.yaml`、`A6*.yaml` 及对应断言。可与 T4、T5 并行。按约定的用例发现方式接入 T1 的运行器。
- **动作** `--case A5` 通过真实 GPIO 事件复现已保存 Day 而仪表临时为 Night。`--case A6` 复现已保存 Night 而关灯后仪表为 Day。分别保留仪表换色和 Theme 打开帧。A5 另保留短按后的焦点及标记帧。从进入 Theme 的动作起，观察到末次稳定取帧且再保持 500 ms 无输入。读取同一次运行内整个窗口的串口。
- **完成标准** A5、A6 的配色时序、高亮和标记全部符合矩阵。两个窗口内主题写入与手动配色事件计数均为零，且已有的实际保存及灯光事件在窗口外可查。主机冒烟、同版构建及场景验证通过。

## T4 · 验证双向保存、即时刷新与重启恢复

- **依赖与范围** 依赖 T1、T2。只新增 `test/wokwi/theme_menu_focus/A4*.yaml`、对应断言和场景专用 EN 接线。可与 T3、T5 并行。
- **动作** 以 `--case A4 --reference-build-dir "$ref/build/test-wokwi"` 跑两个方向，基线和候选移动到相同目标选项再长按。对照 Display 标题、按键提示及共享主题事件。两端在稳定帧后保持相同的 500 ms 无输入时段再结束对照窗口，然后在候选的同一模拟实例内复位。等待下一次启动后重新导航。若 EN 在当前 Wokwi 版本不生效，按方案使用已授权、能运行相同测试固件的 ESP32／ILI9341 台架取证。
- **完成标准** 两个方向都从实际保存成功开始，重启前展示选中配色及值，真实重启后从闪存恢复并定位到新主题。记录两次启动间的连续动作及首次重开画面。与 T1 对照的共享样式观察结果一致。主机冒烟、同版构建及本组必做验收通过。

## T5 · 验证旧主题值按原值加载和显式修正

- **依赖与范围** 依赖 T1、T2。只新增 `test/wokwi/theme_menu_focus/A8*.yaml`、对应断言和 Legacy NVS CSV。可与 T3、T4 并行。复用运行器的镜像准备接口，按方案使用兼容 Python 环境，并传入 Espressif 生成工具路径。
- **动作** `--case A8 --nvs-gen "$nvs_gen"` 加载包含 Legacy NVS 的测试镜像。在真实启动后，先证实 Display 读到 Legacy。两次进入期间经 Back 返回，保留原值、焦点及无标记证据，再从 GPIO32 长按 Night 并重开。
- **完成标准** 签入的是可复现的数据与场景，构建目录保留临时镜像。核对应用段与同版普通镜像一致，显式长按前无写入且两次仍读 Legacy，长按后成功保存 Night 并显示正确焦点与标记。主机冒烟、同版构建及本组必做验收通过。

## 集成完成条件

T1 → T2 → T3、T4、T5，后三项按场景文件隔离，可独立提交。按最终待验提交重建并执行 `--case all --reference-build-dir "$ref/build/test-wokwi" --nvs-gen "$nvs_gen"`，逐项读回 A1–A8、主机冒烟以及 T1 基线对照。环境缺项时记录实际失败和可复跑命令，当前验收继续待办。主题 Wiki 的现状说明只在实现与实测完成后按证据更新。进入 Develop 以本版方案与本清单的同版确认为准。
